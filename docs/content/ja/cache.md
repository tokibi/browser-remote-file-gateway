# OPFS キャッシュ（任意）

Gateway は Origin Private File System（OPFS）にオブジェクト全体をキャッシュできます。キャッシュ対象になるのは、完全なオブジェクトのサイズが `maxFullObjectCacheBytes` 以下の場合だけです。既定値は `0` で、キャッシュを無効にします。

登録時に上限を指定するか、有効なコントローラーで後から変更します。

```js
const gateway = await RemoteFileGateway.register({
  serviceWorkerUrl: '/remote-file-gateway/service-worker.js',
  scope: '/',
  virtualBase: '/remote-file-gateway/',
  maxFullObjectCacheBytes: 4 * 1024 * 1024,
})

// アプリケーションのポリシーが変わった場合
await gateway.configureCache(8 * 1024 * 1024)
```

この上限は Service Worker ハンドラー単位のポリシーで、同じハンドラーに接続するクライアント間で共有されます。アプリケーションのストレージ予算とデータの機密性に合わせて設定してください。Gateway は古いオブジェクトを削除して合計容量を制限しません。この値で制限されるのは、キャッシュ対象になれる個々のオブジェクトのサイズであり、OPFS 全体の使用量ではありません。

## 読み取りと保存

上限以下のオブジェクトに対する最初のリクエストでは、プロバイダーから完全なレスポンスを取得し、宣言された長さと実際の長さをバインディングと照合します。その後 SHA-256 を計算し、オブジェクト本体を OPFS、メタデータを IndexedDB に保存します。以降のキャッシュ読み取りでは、保存済みメタデータと整合性を検証したうえで、範囲リクエストに必要な `File.slice()` だけを読み取ります。

上限より大きいオブジェクトは OPFS を使わず、プロバイダーの範囲レスポンスから返します。OPFS が利用できない場合、書き込みに失敗した場合、またはキャッシュ項目が古い・破損している場合、Gateway は診断情報を記録し、プロバイダーの範囲読み取りにフォールバックします。通常の範囲読み取りに OPFS は必須ではありません。

キャッシュキーはオブジェクト ID です。不変性を守り、内容が変わった場合は同じ ID を再利用せず、新しい ID で公開してください。後続のバインディング公開時には、メモリ内の解決済みオブジェクト情報とキャッシュバージョン確認が無効化されます。現在のメタデータに一致しない保存済み項目は拒否されます。

## 診断情報

`gateway.diagnostics()` はキャッシュヒット、ミス、書き込み、バイパス、拒否、プロバイダーリクエスト、仮想リクエスト、失敗の直近の記録を返します。計測を始める前に `gateway.resetDiagnostics()` を呼び出してください。診断情報は Service Worker ハンドラー内に保持されるため、登録を共有するクライアントには同じ記録が見えます。

プロバイダーごとの動作は[プロバイダー](./providers.md)、メソッドの詳細は[API と HTTP リファレンス](./reference.md)を参照してください。
